**Scope in force (owner decisions, 2026-10-07).** These narrow what "done" means for launch; rows below are read
against them:

- **Email accounts, no SMS.** Register with email + password, confirm the address with a 6-digit code sent by email,
  sign in with email (or a school-issued username) + password or an emailed one-time code, reset passwords by email,
  change the address at `/change-email` (current password + code to the new address + notice to the old one). A phone
  number is optional profile data only: never a sign-in identifier, never verified, never texted (§33).
- **Email is transactional only.** Codes, password resets, security notices (password changed / reset, one-time
  password set by staff, email changed) and invitations are always sent (`transactional: true`, Resend in production;
  `EMAIL_PROVIDER=resend` is required there). Digests, announcements, reminders, receipts and staff alerts are
  optional email behind `features.email` (off): they stay in the app.
- **Dormant behind the `features` setting** (all off, seeded off in every environment, code kept, a SUPER_ADMIN switches
  each back on at `/admin/settings` with step-up and audit; ARCHITECTURE §3.14): AI (tutor, solver, AI marking, AI
  drafts: §14, §15, §40, §41), the WhatsApp channel (§30), Stripe (§32), SMS and optional email. While a flag is off
  its API routes and webhooks return 404, its pages show the not-found page (under `/app` with HTTP 200, a soft 404,
  because `/app/loading.tsx` streams first; see the email-auth verification run), its menu entries and marketing
  claims are hidden, and no provider is called.
- **Pricing.** FREE preview + **Full access for a one-off USD 1 (lifetime)** via Paynow (EcoCash, OneMoney, cards on
  the Paynow page); the price is a `PlanPrice` row (ONE_OFF, no end date), seeded in every environment and editable in
  `/admin/plans` (§31, ARCHITECTURE §7.5).

**The one-line truth:** the platform is functionally complete for the §52 journey **with development demo content**.
It ships with curriculum *structure* only: production has no verified subjects, no official syllabus versions, no exam
sessions and no published lessons/questions/tests (the one price that exists everywhere is Full access at USD 1). Real
content must be authored or licensed through the CMS (§47; a content pipeline is importing reviewed content in
parallel, `docs/CONTENT_PIPELINE.md`), and the external services that stay on (Resend email, Paynow, object storage)
have never run against the real service.

## Accepted risks

- **Postgres does everything** (queue, search, rate limits, rollups) until the triggers in ARCHITECTURE §2.2.
- **One web node at launch.** Public pages use time-based ISR (`export const revalidate`, up to 1 h; `/daily` 5 min),
  so a CMS publish or correction can take up to an hour to show on public pages; a shared cache handler is needed
  before a second web node (ARCHITECTURE §3.8).
- **Bundle sizes** above the documented budgets (framework floor) on a low-bandwidth audience.
- **Performance numbers** come from a shared Windows laptop with synthetic data; no production-like load test yet.
- **Grade estimates** use flagged estimate schemes until real boundaries are entered.
- **First runs in staging**: Docker image, compose stack, CI workflow, S3, Paynow, Resend email (Stripe, WhatsApp, SMS
  and AI are switched off and get their first live run only when the owner switches them on).
- **Maths over WhatsApp** is limited to channel-safe questions (plain-text readable).

- **Import parsing under load.** `read-excel-file` halves its parse chunk whenever a chunk takes more than 7 ms and
  recurses per chunk, so a large but legitimate cell can overflow the stack on a busy CPU (seen once in the full test
  run; ARCHITECTURE risk T13). Imports fail cleanly when it happens; fix before large roster/content imports.
