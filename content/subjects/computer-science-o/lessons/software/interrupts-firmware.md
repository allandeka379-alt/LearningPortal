## Introduction

Farai presses the power button on his laptop in Harare. For a second or two nothing seems to happen; then a logo appears, and soon the login screen. In those seconds a small program stored permanently on a chip woke the hardware up, checked it and loaded the operating system from the storage drive into memory. Later, while a video is downloading, he presses a key and the letter appears at once, even though the processor was busy. Both events are part of this lesson: **firmware** that starts the computer, and **interrupts** that let the processor respond to events immediately.

Cambridge 0478 (topic 4.1) asks you to understand how hardware, firmware and an operating system are needed to run application software, and to describe how interrupts are generated and handled. Interrupt questions often carry three or four marks for a clear sequence of steps.

## Key definitions

:::definition{term="Firmware"}
A program stored permanently in non-volatile memory (ROM or flash memory) on the hardware, which controls the hardware at a basic level; the bootloader is an example.
:::

:::definition{term="Bootloader"}
The firmware that runs when the computer is switched on; it checks the hardware and loads the operating system from secondary storage into RAM so that it can start.
:::

:::definition{term="Interrupt"}
A signal sent from a device or from software to the processor, indicating that an event needs attention.
:::

:::definition{term="Interrupt service routine (ISR)"}
A short program, part of the operating system or a device driver, that is run to deal with one particular type of interrupt.
:::

## Hardware, firmware, operating system and applications

Software runs in layers, each one running on the layer below it:

| Layer | Example | Runs on |
|:--|:--|:--|
| Application software | A spreadsheet | The operating system |
| Operating system | Manages files, memory, devices | The firmware (the bootloader loads and starts it) |
| Firmware (bootloader) | Stored in ROM or flash memory on the motherboard | The hardware |
| Hardware | Processor, RAM, storage, devices | — |

When the computer is switched on, RAM is empty because it is volatile. The processor therefore starts by running the **bootloader**, which is held in non-volatile memory and so is always available. The bootloader tests the hardware, finds the operating system on the storage device and loads it into RAM. Only then can the OS start, and only when the OS is running can the user open applications, which request services from the OS. The application cannot run directly on the hardware, and the OS cannot load itself.

## Interrupts

A processor is busy running instructions almost all the time. Without interrupts, it would have to keep checking every device ("has a key been pressed? has the printer finished?"), wasting time. Instead, a device or a program sends an **interrupt** when something needs attention.

### How interrupts are generated

| Type | Generated by | Examples |
|:--|:--|:--|
| Hardware interrupt | A hardware device | A key is pressed on the keyboard; the mouse is moved; the printer runs out of paper or its buffer is empty; a disk finishes reading data |
| Software interrupt | A running program or the operating system | Division by zero; two processes try to access the same memory location; a program asks the OS for a service; a program error |

### How an interrupt is handled

1. A device or program generates an interrupt signal, which is sent to the processor.
2. Interrupts have **priorities**. At the end of each fetch-decode-execute cycle the processor checks whether an interrupt is waiting.
3. If an interrupt of higher priority than the current task is waiting, the processor **saves the current state** of the task (the contents of its registers, such as the program counter) so that it can be resumed later.
4. The processor identifies the source of the interrupt and runs the matching **interrupt service routine**.
5. When the ISR has finished, the processor **restores** the saved state and continues the original task from where it stopped, or checks for further interrupts. A lower-priority interrupt waits until the current task can be paused.

### What happens as a result

The outcome depends on the interrupt: the key pressed is stored and displayed; a message "printer out of paper" is shown to the user; more data is sent to the printer's buffer; a program that divided by zero is stopped and an error is reported; the OS stops one of two processes from writing to the same memory location. Because the processor returns to its previous task afterwards, many tasks can be handled efficiently and the user sees the computer respond immediately.

:::example
**A printer runs out of paper.** Chipo prints a 20-page report in a school in Kwekwe.

1. The printer detects the empty tray and sends a **hardware interrupt** to the processor.
2. At the end of its current fetch-decode-execute cycle, the processor finds the interrupt waiting; its priority is higher than the background task.
3. The processor saves the contents of its registers for the current task.
4. It runs the ISR for the printer, which displays the message "Printer out of paper" on Chipo's screen.
5. The saved register contents are restored and the processor carries on with its previous task. When Chipo loads paper, printing continues.
:::

:::example
**Division by zero.** A program calculates an average by dividing a total by the number of results, but no results were entered, so it tries to divide by 0.

1. The processor cannot carry out the division, so a **software interrupt** is generated.
2. The processor saves the state of the program and runs the ISR for this error.
3. The OS stops the program (or passes the error to it to handle) and reports an error message such as "division by zero".
4. The processor then continues with other tasks. A well-written program avoids this by checking that the count is greater than 0 before dividing.
:::

## Common mistakes

:::mistake{title="Saying the operating system is stored in ROM"}
In a PC the OS is stored on secondary storage (hard disk or SSD) and **loaded into RAM** by the bootloader. Only the firmware is in ROM or flash memory.
:::

:::mistake{title="Saying the processor stops working when an interrupt arrives"}
The processor finishes its current cycle, saves the current task's state, runs the ISR and then **resumes** the task.
:::

:::mistake{title="Forgetting priorities"}
An interrupt is only serviced straight away if its priority is higher than the current task; otherwise it waits.
:::

## Exam tips

:::exam-tip
For "**describe** how an interrupt is handled", give the steps in order: signal sent → checked at end of the FDE cycle → priority compared → current state (registers) saved → ISR identified and run → state restored and task resumed.
:::

:::exam-tip
Learn two examples of each kind: **hardware** (key press, mouse moved, printer out of paper) and **software** (division by zero, two processes accessing the same memory location).
:::

## Summary

:::summary
- Applications run on the operating system; the OS is loaded and started by the firmware (bootloader); the firmware runs on the hardware.
- Firmware is stored in non-volatile ROM or flash memory, so it is available as soon as the power is on.
- An interrupt is a signal to the processor that an event needs attention; hardware interrupts come from devices, software interrupts from programs.
- The processor checks for interrupts after each FDE cycle, saves its current state, runs the interrupt service routine, then restores the state and resumes.
:::
